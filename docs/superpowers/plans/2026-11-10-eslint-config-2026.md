# @cospired ESLint configs 2026 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the legacy airbnb/eslintrc `@cospired/eslint-config-*` packages with flat-config ESLint 10 packages (`base`, `react`, each with JS and TypeScript variants, plus a node entry), tested for completeness, released as 8.0.0.

**Architecture:** npm workspace with two ESM packages. Each package exports config(s) built from small rule modules in `src/rules/`. A shared test helper lints fixture code through the ESLint Node API. Rule decisions that conflict are placeholders until the interactive rule review (Task 8).

**Tech Stack:** ESLint 10, `@eslint/js`, typescript-eslint 8, eslint-plugin-import-x, `@eslint-community/eslint-plugin-eslint-comments`, eslint-plugin-todo-plz, `@stylistic/eslint-plugin`, eslint-config-prettier, eslint-plugin-react-hooks, -react-refresh, -jsx-a11y, -formatjs, `node:test`, changesets, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-10-eslint-config-2026-design.md` (read it first, including "Findings from eventured consumers").

## Global Constraints

- Flat config, ESLint 10, typescript-eslint 8+, ESM only. No airbnb, no hapi plugin, no Babel/tape/`eslint-find-rules`/`in-publish`/`safe-publish-latest`/Travis.
- Packages: `@cospired/eslint-config-base` (`.` JS, `./typescript`, `./node`) and `@cospired/eslint-config-react` (`.` JS, `./typescript`). Both released as `8.0.0`. Delete `packages/eslint-config-typescript`.
- `react` depends on `base` (regular dependency); `react/typescript` extends `base/typescript`. `base` has no React rules and no React peers.
- Peer dependencies are ranges, not exact pins; they must include ESLint 10, typescript-eslint 8.72, TypeScript 6, Prettier 3.9.
- Carry over: `eslint-disable` needs `-- reason`; TODOs need `#\d+` ticket (`todo-plz/ticket-ref`); alphabetized `import-x/order`; devDependency imports only in test/config/script files (eventured's glob list, overridable via option).
- Prettier owns formatting; `eslint-config-prettier` goes last.
- Warnings are failures in consumers (`--max-warnings 0`): prefer `error`/`off`.
- Defaults moved into the shared TS configs (Dirk-approved): `@typescript-eslint/explicit-function-return-type` (`{ allowExpressions: true }`, non-test files only), `@typescript-eslint/no-misused-promises` (`{ checksConditionals: { flagUnions: 'strict' } }`), `@typescript-eslint/no-generated-empty-object-type: 'error'`.
- `tsconfigPath` accepts a string or array; `tsconfigRootDir` stays an option; `import-x/resolver` typescript settings with `noWarnOnMultipleProjects` follow eventured's `node.js`.
- Rule conflicts are decided one by one with Dirk (Task 8); until then keep eventured's setting and list the rule as open.
- Eventured source: `/Users/dh/projects/eventured/eventured/packages/eslint-config/src/{base,node,react}.js`. Old rules: `packages/eslint-config-{base,react}/rules/*.js` (read via `git show main:<path>` once the packages are rewritten).

## Review Focus

- A TS file not covered by any given tsconfig: lint reports a clear parse error for that file, no crash or hang (Task 4).
- `.mjs`/`.cjs`/`.js` config and script files under the TS configs: linted without type-aware errors, node globals where intended (Task 4).
- `#alias` subpath imports and relative workspace imports: no `import-x/no-unresolved` false positives, and `importOrder.pathGroups` option groups them (Task 4).
- Test files: exempt from `explicit-function-return-type` and allowed devDependency imports; non-test files are not (Task 4).
- Calling a `create*Config` function twice with different options returns independent arrays (no shared mutated state), and JSX parses in `.jsx`/`.tsx` under the react configs (Tasks 4, 6).
